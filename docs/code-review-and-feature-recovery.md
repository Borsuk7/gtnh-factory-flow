# GTNH Planner code review and feature recovery report

**Compiled:** 2026-11-16

**Review baseline:** `47d692d5` (2026-10-20). Key references were spot-checked at `80b5e03b`; this is not a fresh review of all intervening changes.

The biggest cleanup opportunity is retired UI that still carries state, actions, and tests. The biggest recovery opportunity is planning functionality that disappeared in a UI or solver migration: selection analysis, machine comparison, reusable blueprints, and bottleneck exploration. **No production caller** is evidence that code is disconnected today; it does not establish that the feature should stay gone.

## The optimizer and explanations need different decisions

**Machine sizing is useful.** The optimizer seeded demand from legacy output targets or inferred demand from terminal machines and loops, propagated it through the graph, and rounded suggested counts up. Both global and per-machine controls were removed in [`dd86755c`](https://github.com/Borsuk7/gtnh-factory-flow/commit/dd86755c). Its assumptions predate current port rates, count pins, and drawer rules. Restoring it verbatim would risk two inconsistent answers for the same plan. A modern replacement could use the current solver, preview whole-machine counts, and recheck the plan after applying the proposed counts. Compare old branch and loop fixtures to see which behaviors should carry over.

**The most valuable missing explanation is what to fix next.** The old port and wire stories answer what moved, what was requested, and why the two differ. The old usage panel went further: it named the current constraint and showed up to two possible next limits. [Current card tooltips](../src/components/flow/clean/menus/card-tips.ts) already explain several immediate causes, including starvation and clogs. Recover the ranked view where it adds information, and validate any prediction against the current solver. A ranked list of observed caps is not proof that removing one cap leaves every other flow unchanged.

## Suggested order of work

1. **Start with straightforward cleanup:** remove the dead prop chain and unused symbols, retire the public-viewer path, and remove disconnected UI shells once their useful behavior has been accounted for.
2. **Recover the strongest planning features:** selection analysis, machine comparison, reusable blueprints, then bottleneck exploration. Keep these separate so each can be tested against current plans.
3. **Decide what to do with larger legacy pieces:** automatic sizing, the Pool workflow, and the old export path. Preserve legacy imports, parity fixtures, and shared diagnostics while shrinking inactive runtime branches.
4. **Verify at the behavior boundary:** run typecheck and the full suite for implementation changes; use headless Playwright for restored UI. Profile changes that affect board performance.

The original review's normal typecheck passed; the stricter unused-locals/parameters check reported 18 diagnostics. The full suite was not verified: Vite hit Windows sandbox temp-cache rename errors before tests ran, and retry runs were stopped without a result. This report documents findings only; it does not implement cleanup or restoration.
